# AGENTS.md

> Карта проекта для AI-агентов. Держать в актуальном состоянии при изменении структуры, команд, правил установки или набора скилов.

## Обзор проекта

`eda` — npm-пакет `@gian-tiaga/eda` с CLI для установки и обновления русскоязычных AI-скилов `eda-*` в проектах пользователя.

Пакет поддерживает две среды:

- Claude Code: установка в `.claude/skills/<skill>/SKILL.md`
- Codex CLI: установка в `.codex/skills/<skill>/SKILL.md`

Главная идея проекта: хранить исходники скилов в `skills/*.md`, а CLI `eda init` / `eda update` / `eda update-all` синхронизирует их в целевые директории проекта пользователя. Корневой `AGENTS.md` в проектах пользователей установщик не трогает.

## Стек

- Runtime: Node.js `>=18`
- Module system: ESM (`"type": "module"`)
- CLI entry: `bin/cli.js`
- Installer logic: `lib/install.js`
- Tests: Node.js built-in test runner (`node --test`)
- Interactive prompts: `@inquirer/checkbox`, `@inquirer/select`
- Package manager: npm

## Команды

```bash
npm test
node bin/cli.js --help
node bin/cli.js --version
node bin/cli.js init
node bin/cli.js update
node bin/cli.js update-all [dir]
```

`init` и `update` интерактивны при TTY. В неинтерактивном режиме установщик выбирает Claude Code и Codex CLI, а настройки создаёт со значениями по умолчанию. `update-all` не интерактивен, ищет проекты с уже установленными скилами на глубине 2 и настройки не создаёт.

## Ключевые файлы

| Файл | Назначение |
|---|---|
| `bin/cli.js` | Разбирает команды `init`, `update`, `update-all`, `--version`, `--help`; печатает ошибки и завершает процесс |
| `lib/install.js` | Основная логика установки, обновления, создания `docs/settings.yaml`, удаления старых форматов и retired-скилов |
| `skills/*.md` | Исходники скилов в Markdown с YAML front matter |
| `test/install.test.js` | Контракт установки, настройки по умолчанию, проверки содержимого скилов |
| `README.md` | Публичное описание поведения; обновлять вместе с изменениями CLI или скилов |

## Правила для агентов

- Работай на русском языке: проект, README и скилы написаны для русскоязычного пользователя.
- Перед изменением поведения CLI читай `lib/install.js`, `bin/cli.js`, `README.md` и релевантные тесты.
- Перед изменением скила читай соседние `skills/eda-*.md`: у них должен оставаться единый стиль, структура и терминология.
- Не редактируй установленные копии в `.claude/skills/` или `.codex/skills/` как источник правды. Источник правды — только `skills/*.md`.
- Не добавляй новые runtime-зависимости без необходимости. Для простого поведения предпочитай стандартные модули Node.js.
- Не используй команды с интерактивным вводом в автоматических тестах.
- Не обходи pre-commit/pre-push hooks через `--no-verify`.
- Не коммить секреты, токены, `.env` и локальные артефакты.

## Правила изменения CLI

- `eda init` должен спрашивать целевые среды при интерактивном TTY и выбирать обе среды без TTY.
- `eda update` должен обновлять только уже найденные среды. Если `.claude/skills` и `.codex/skills` отсутствуют, он просит сначала запустить `eda init`.
- `eda update-all [dir]` должен обходить указанную директорию, её прямых детей и внуков. Проект считается найденным только при наличии `.claude/skills` или `.codex/skills`.
- `eda update-all` должен обновлять только найденные среды, не создавать `docs/settings.yaml`, не заходить в `.git`, `.claude`, `.codex`, `node_modules` и не следовать symlink-директориям.
- Ошибка обновления одного проекта в `eda update-all` не должна останавливать остальные проекты; в конце нужна сводка по успехам, пропускам и ошибкам.
- `docs/settings.yaml` создаётся только если его ещё нет. Существующий файл нельзя перезаписывать.
- Для Codex формат установки — директория с `SKILL.md`: `.codex/skills/<skill>/SKILL.md`.
- Старый Codex-формат `.codex/skills/<skill>.md` удаляется при обновлении соответствующего скила.
- Retired-скилы удаляются из всех установленных целевых сред.
- `AGENTS.md` в проектах пользователей установщик не создаёт и не перезаписывает.

## Правила изменения скилов

- Каждый скил должен быть самостоятельной инструкцией и иметь front matter:

```markdown
---
name: eda-...
description: '...'
---
```

- `description` в front matter каждого скила должен быть не длиннее 1024 символов.
- В каждом packaged `eda-*` скиле должна быть ровно одна секция `## Вход из сообщения пользователя`.
- Если скил зависит от настроек, явно документируй чтение `docs/settings.yaml` и значения по умолчанию.
- Интерактивные вопросы формулируй через общий паттерн `AskUserQuestion`: Claude Code, Codex interactive и неинтерактивный Codex должны быть описаны отдельно.
- Обычные мета-проверки `eda-plan` и `eda-review-check` в интерактивном Codex должны идти через субагентов (`spawn_agent` или аналог). Отдельные `codex exec` используй только как fallback для неинтерактивного Codex или как strict-кросс-проверку соседним CLI.
- Сохраняй жёсткие границы ответственности:
  - `eda-roadmap` создаёт список будущих задач, но не пишет детали реализации.
  - `eda-start` собирает требования и стартовые решения нового проекта, но не пишет код и не ставит зависимости.
  - `eda-explore` исследует, но не пишет план реализации.
  - `eda-plan` планирует, но не меняет код.
  - `eda-plan-polish` сразу запускает три изолированных полных ревью готового плана на быстрой, кодовой и флагманской моделях с одним общим промптом, после их ответов выставляет оценку 0–100, при оценке ниже порога правит только файл плана и запускает новую итерацию; код не меняет и проверки проекта не запускает.
  - `eda-execute`, `eda-fix`, `eda-fix-by-review` меняют код и проверяют результат.
  - `eda-manual-test` вручную проверяет API/UI после изменений и сохраняет отчёт, но не правит код, не пишет автотесты и не коммитит.
  - `eda-review` пишет первичное ревью, но не правит код.
  - `eda-review-check` проверяет и правит готовое ревью, но не делает новое ревью и не правит код.
  - `eda-polish` оркестрирует цикл `review draft` / `review-check` / `fix-by-review`, но не делает эти шаги основным агентом и не коммитит.
  - `eda-send-review` отправляет готовое ревью, но не делает новое.
  - `eda-commit` коммитит готовые изменения, но не дописывает логику.
  - `eda-worktree` создаёт отдельный git worktree и ветку, но не правит код.
  - `eda-merge-worktree` мержит ветку из worktree в текущую, но не удаляет worktree и ветку.
  - `eda-automate` предлагает автоматизации, но не внедряет их.

## Проверки перед финалом

Минимальная проверка после изменений:

```bash
npm test
```

Если менялось поведение CLI, дополнительно проверь:

```bash
node bin/cli.js --help
node bin/cli.js --version
```

Если менялись тексты скилов, убедись, что README не расходится с реальным списком скилов, флагов, настроек и директорий установки.

## Документация

При изменении пользовательского поведения обновляй `README.md` в том же изменении:

- команды и их вывод;
- формат установки;
- список скилов;
- настройки `docs/settings.yaml`;
- retired-скилы или миграции старого формата.

Для внутренних инструкций агентам обновляй этот файл.
