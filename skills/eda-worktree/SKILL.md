# Скил: Создатель worktree (eda-worktree)

Работай как лёгкий оркестратор установленного агента `eda-worktree-executor`. Сам не исследуй git-состояние, не выбирай имя или базу и не выполняй команды.
Создаваемые директория и ветка используют шаблон `{name}-work-{n}`.

## Вход из сообщения пользователя

Сохрани весь текст текущего сообщения дословно в `$USER_REQUEST`. Это главный вход: базовая ветка или ref, ограничения и прямые указания.
Базовую ветку берёт из текста рядом с вызовом исполнитель; если она не указана, он возвращает вопрос.

Старое обсуждение в истории не считай входом, если пользователь не связал его с текущим вызовом явно. При последующем ответе на вопрос сохрани исходный `$USER_REQUEST` и передай ответ отдельно.

## Агент

| Агент | Claude Code | Codex | Доступ |
|---|---|---|---|
| `eda-worktree-executor` | `haiku` | `gpt-5.6-luna` | git-write |

- В Claude Code запускай установленный custom agent через `Agent` tool по имени.
- В Codex запускай установленный custom agent через `spawn_agent` или аналог по имени.
- Не копируй в task-сообщение системный prompt агента: он уже установлен в `.claude/agents/` или `.codex/agents/`.
- Передавай агенту только рабочую директорию, данные текущего запуска и требуемый формат результата.
- Если custom agent или инструмент субагентов недоступен, остановись: `blocked: нужен установленный агент eda-worktree-executor`. Не выполняй его роль основным агентом и не заменяй отдельным CLI-процессом.

## Технические остановки субагентов

Техническую ошибку инструмента субагентов не смешивай со статусами `failed` и `blocked` содержательного контракта. Сохрани полный исходный текст ошибки и обработай её по причине:

- лимит параллельности или отсутствие свободного слота — дождись уже запущенного этим workflow агента, при необходимости закрой завершённые потоки и повтори тот же запуск; если управляемых активных агентов нет, заверши `blocked: заняты слоты субагентов`;
- лимит глубины вложения — не повторяй запуск и не выполняй работу сам; заверши `blocked: достигнут лимит глубины субагентов`, указав наблюдаемую и требуемую глубину;
- исчерпана usage-квота — не делай автоматических повторов; заверши `blocked: исчерпана квота`, сохрани время reset или условие продолжения, если хост его сообщил;
- не хватает разрешения — запроси одно конкретное разрешение по правилам текущей среды и после ответа продолжи того же агента; в неинтерактивной среде заверши `blocked: нужно разрешение пользователя`;
- временная API-, server-, overload- или network-ошибка — один раз продолжи того же агента; если resume недоступен, один раз запусти ту же роль с исходным входом, полным частичным результатом и требованием сначала сверить текущее состояние; повторный такой сбой заверши как `blocked` с исходной ошибкой;
- неизвестная техническая ошибка — не угадывай причину и не зацикливай retry; заверши `blocked: техническая ошибка субагента` с полным исходным текстом.

Ожидание слота и один технический retry не разрешают создавать второй worktree без сверки текущего состояния.

## Интерактивные вопросы

Когда агент вернул `blocked`, задай его один конкретный вопрос пользователю через общий паттерн `AskUserQuestion`.

- Claude Code: используй `AskUserQuestion`.
- Codex interactive: используй `request_user_input`, если доступен; иначе задай один короткий вопрос с 1–3 вариантами и остановись до ответа.
- Codex exec / неинтерактивный запуск: не читай stdin; заверши со статусом `blocked: нужен ответ пользователя`, перечисли вопрос и варианты.
- Не запускай команды, которые ждут интерактивного ввода в терминале.

После ответа продолжи того же агента, если хост это поддерживает. Иначе запусти `eda-worktree-executor` заново с исходным запросом, полным предыдущим результатом и ответом пользователя.

## Процесс

Запусти `eda-worktree-executor` и передай:

```text
Рабочая директория: <cwd>
USER_REQUEST:
<полный дословный запрос>

Верни результат строго по YAML-контракту агента.
```

Обработай `status`:

- `created` — переходи к финалу;
- `blocked` — задай вопрос агента и продолжи после ответа;
- `failed` — коротко сообщи фактическую ошибку и безопасный следующий шаг.

## Финал

Для `created` коротко сообщи из результата агента:

- созданный путь worktree;
- имя ветки;
- выбранную базу;
- предупреждение о незакоммиченных изменениях, если оно есть;
- команду `cd "<worktree_path>"`;
- что обратный merge выполняет `eda-merge-worktree <n>` или `eda-merge-worktree work-<n>`.

## Чего НЕ делать

- Выполнять работу `eda-worktree-executor` основным агентом.
- Править код, docs, конфиги или зависимости.
- Коммитить, пушить, мержить или удалять worktree и ветки.
- Терять исходный `$USER_REQUEST` после интерактивного ответа.
