# Скил: Merge из worktree (eda-merge-worktree)

Работай как лёгкий оркестратор установленного агента `eda-merge-worktree-executor`. Сам не исследуй git-состояние, не определяй исходную ветку и не выполняй merge.

## Вход из сообщения пользователя

Сохрани весь текст текущего сообщения дословно в `$USER_REQUEST`. Это главный вход: номер worktree, короткое имя или полное имя, ограничения и прямые указания. Аргумент принимает как `1`, `work-1` или `{name}-work-1`.

Старое обсуждение в истории не считай входом, если пользователь не связал его с текущим вызовом явно. При последующем ответе на вопрос сохрани исходный `$USER_REQUEST` и передай ответ отдельно.

## Агент

| Агент | Claude Code | Codex | Доступ |
|---|---|---|---|
| `eda-merge-worktree-executor` | `haiku` | `gpt-5.6-luna` | git-write |

- В Claude Code запускай установленный custom agent через `Agent` tool по имени.
- В Codex запускай установленный custom agent через `spawn_agent` или аналог по имени.
- Не копируй в task-сообщение системный prompt агента: он уже установлен в `.claude/agents/` или `.codex/agents/`.
- Передавай агенту только рабочую директорию, данные текущего запуска и требуемый формат результата.
- Если custom agent или инструмент субагентов недоступен, остановись: `blocked: нужен установленный агент eda-merge-worktree-executor`. Не выполняй его роль основным агентом и не заменяй отдельным CLI-процессом.

## Интерактивные вопросы

Когда агент вернул `blocked`, задай его один конкретный вопрос пользователю через общий паттерн `AskUserQuestion`.

- Claude Code: используй `AskUserQuestion`.
- Codex interactive: используй `request_user_input`, если доступен; иначе задай один короткий вопрос с 1–3 вариантами и остановись до ответа.
- Codex exec / неинтерактивный запуск: не читай stdin; заверши со статусом `blocked: нужен ответ пользователя`, перечисли вопрос и варианты.
- Не запускай команды, которые ждут интерактивного ввода в терминале.

После ответа продолжи того же агента, если хост это поддерживает. Иначе запусти `eda-merge-worktree-executor` заново с исходным запросом, полным предыдущим результатом и ответом пользователя.

## Процесс

Запусти `eda-merge-worktree-executor` и передай:

```text
Рабочая директория: <cwd>
USER_REQUEST:
<полный дословный запрос>

Верни результат строго по YAML-контракту агента.
```

Обработай `status`:

- `merged` или `already-up-to-date` — переходи к финалу;
- `conflict` — сообщи список конфликтных файлов и что merge нужно завершить вручную;
- `blocked` — задай вопрос агента и продолжи после ответа;
- `failed` — коротко сообщи фактическую ошибку и безопасный следующий шаг.

## Финал

Коротко сообщи из результата агента:

- исходную и текущую ветки;
- путь исходного worktree;
- статус: `merged`, `already up to date` или `conflict`;
- что worktree и исходная ветка не удалялись.

После успешного merge скил не удаляет worktree и ветку.

## Чего НЕ делать

- Выполнять работу `eda-merge-worktree-executor` основным агентом.
- Переключать целевую ветку, править код или разрешать конфликты вручную.
- Делать отдельный commit, push или cleanup worktree и исходной ветки.
- Терять исходный `$USER_REQUEST` после интерактивного ответа.
