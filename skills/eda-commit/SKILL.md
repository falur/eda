# Скил: Коммитер (eda-commit)

Работай как лёгкий оркестратор установленного агента `eda-commit-executor`. Сам не исследуй diff, не выбирай файлы, не составляй commit message и не выполняй git/GitHub-команды.

## Вход из сообщения пользователя

Сохрани весь текст текущего сообщения дословно в `$USER_REQUEST`. Это главный вход, а не только слова после имени скила или последний вопрос.

Извлеки `$REQUESTED_ACTIONS`: ограничения и цепочку действий после коммита — `push`, отправить ветку, создать или обновить PR, вернуть ссылку, merge, переключить или удалить ветку. Поздний общий вопрос не отменяет конкретную команду из более ранней части того же сообщения.

Извлеки `$COMMIT_SCOPE`: явно названные файлы, каталоги, задача или другое ограничение состава коммита. Само имя `eda-commit` и действия после коммита не задают scope. Если такого контекста нет, оставь `$COMMIT_SCOPE` пустым: это означает охватить все незакоммиченные содержательные изменения, а не вопрос о выборе файлов.

Пример: `eda-commit сразу отправь ветку и создай PR и дай ссылку` означает `commit → push → create-or-find PR → return URL`. После коммита не спрашивай, что делать дальше.

При последующих уточнениях более поздняя явная команда или запрет имеют приоритет, но короткий ответ не заменяет остальной `$USER_REQUEST`. Историю прошлых сообщений используй только если пользователь явно связал её с текущим вызовом.

## Агент

| Агент | Claude Code | Codex | Доступ |
|---|---|---|---|
| `eda-commit-executor` | `haiku` | `gpt-5.6-luna` | git-write |

- В Claude Code запускай установленный custom agent через `Agent` tool по имени.
- В Codex запускай установленный custom agent через `spawn_agent` или аналог по имени.
- Не копируй в task-сообщение системный промпт агента: он уже установлен в `.claude/agents/` или `.codex/agents/`.
- Передавай агенту только рабочую директорию, данные текущего запуска и требуемый формат результата.
- Если custom agent или инструмент субагентов недоступен, остановись: `blocked: нужен установленный агент <имя>`; не выполняй его роль основным агентом и не заменяй отдельным CLI-процессом.

## Интерактивные вопросы

Когда агент вернул `blocked`, задай его один конкретный вопрос пользователю.

- Claude Code: используй `AskUserQuestion`.
- Codex interactive: используй `request_user_input`, если доступен; иначе задай короткий вопрос с вариантами 1–3 и остановись до ответа.
- Codex exec / неинтерактивный запуск: не читай stdin; заверши со статусом `blocked: нужен ответ пользователя`, перечисли вопрос и варианты.
- Никогда не задавай общий вопрос о дальнейших действиях, если `$REQUESTED_ACTIONS` уже содержит их.

После ответа сохрани исходный `$USER_REQUEST`, добавь новый ответ и продолжи того же агента, если хост это поддерживает. Иначе запусти этого же custom agent заново с предыдущим результатом, актуальным состоянием и ответом.

## Процесс

### 1. Сделать коммиты и продолжение

Запусти `eda-commit-executor`. Передай:

```text
Рабочая директория: <cwd>
USER_REQUEST:
<полный дословный запрос>

REQUESTED_ACTIONS:
<цепочка действий>

COMMIT_SCOPE:
<явный контекст состава или пусто>

Верни результат строго по YAML-контракту агента.
```

Агент сам собирает git-контекст, читает правила и историю, формирует сообщения, точечно коммитит и выполняет разрешённое продолжение. При непустом `$COMMIT_SCOPE` он выбирает соответствующий состав. При пустом `$COMMIT_SCOPE` включает все tracked-изменения и содержательные untracked-файлы, исключая только очевидные кэши, временные, системные и локальные служебные артефакты. Выбранный состав он сам делит на необходимое число логически цельных коммитов и создаёт их по порядку; несколько задач в полном дефолтном наборе не являются причиной для вопроса. При вероятном секрете или другой реальной небезопасности он обязан вернуть `blocked` до индексации затронутой группы.

Явная команда пользователя разрешает обычные ожидаемые действия и безопасные предпосылки в её рамках. Например, «создай PR» разрешает обычный push текущей ветки, если без него PR создать нельзя. Она не разрешает force-push, публикацию секретов или другое не названное рискованное действие.

Обработай `status`:

- `empty` — сообщи, что коммитить нечего, и закончи;
- `blocked` — задай только конкретный вопрос агента и продолжи его после ответа;
- `committed` — если продолжение не было задано, задай вопрос из следующего этапа;
- `completed` — если push выполнен, а PR нет, задай вопрос из следующего этапа, иначе переходи к финалу;
- `partial` — переходи к финалу.

При продолжении передай тому же агенту исходный `$USER_REQUEST`, актуальные `$REQUESTED_ACTIONS`, полный предыдущий результат и новый ответ пользователя. Не теряй список созданных коммитов и уже выполненные действия.

### 2. Решить, нужен ли вопрос после коммитов

Если `$REQUESTED_ACTIONS` пуст и статус `committed`, спроси пользователя, используя только применимые варианты, которые вернул executor после создания всех запланированных коммитов:

- push;
- создать PR и дать ссылку;
- merge в основную ветку, переключение и удаление текущей ветки;
- ничего больше.

Если push выполнен, а PR текущей ветки нет (`pr.status: absent`), спроси один раз, создавать ли PR: «создать PR» или «оставить ссылку на создание». Не спрашивай, если PR уже есть или пользователь его запретил.

Если других вопросов нет и вся запрошенная цепочка выполнена, сразу переходи к финалу.

Передай выбор тому же `eda-commit-executor` вместе с полным предыдущим результатом. Основной агент команды не выполняет.

### 3. Финал

Коротко сообщи из результата executor:

- hash и заголовок каждого созданного коммита по порядку;
- какие действия выполнены после серии коммитов;
- номер и фактический URL PR, если есть;
- текущую ветку;
- оставшиеся незакоммиченные файлы.

Если push выполнен, ссылка обязательна всегда: URL существующего или созданного PR, иначе `pr.create_url` — ссылку на создание PR. Если executor вернул обе ссылки пустыми, прямо скажи, что ссылку получить не удалось, и назови причину.

Для `partial` сначала назови выполненные действия, затем ошибку и следующий безопасный шаг.

## Чего НЕ делать

- Выполнять работу `eda-commit-executor` основным агентом.
- Делить сбор контекста и коммит между разными агентами или выполнять повторный модельный проход без блокера.
- Пересказывать предыдущий результат вместо передачи полного YAML при продолжении.
- Терять начало `$USER_REQUEST` из-за последующего вопроса или ответа.
- Спрашивать про push или PR, если пользователь уже явно приказал выполнить их.
- Заканчивать выполненный push без ссылки на PR или на его создание.
- Отключать hooks, использовать `--amend`, делать force-push в `main`/`master` или создавать дубликат PR.
- Делать ревью или править логику кода — это другие скилы.
